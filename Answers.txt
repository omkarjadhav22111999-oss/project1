1. In this code base, we have some different implementation strategies when it comes to database access layer and manipulation. If you would maintain this code base, would you refactor any of those? Why?
Answer - Yes, I would refactor the database access layer to use a consistent repository/service pattern, reducing duplication and improving maintainability, testability, and separation of concerns.

2. When it comes to API spec and endpoints handlers, we have an Open API yaml file for the Warehouse API from which we generate code, but for the other endpoints - Product and Store - we just coded directly everything. What would be your thoughts about what are the pros and cons of each approach and what would be your choice?
Answer - OpenAPI generation provides consistency, validation, and contract-first development, while manual coding offers flexibility and simplicity; I would use OpenAPI for all APIs to ensure consistent, maintainable contracts.

3. Given the need to balance thorough testing with time and resource constraints, how would you prioritize and implement tests for this project? Which types of tests would you focus on, and how would you ensure test coverage remains effective over time?
Answer - I would prioritize unit and integration tests for critical business logic and APIs, add end-to-end tests for key flows, and continuously monitor coverage through CI with coverage thresholds and regression tests.
